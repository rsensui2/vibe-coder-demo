# PriceRadar — Product Spec

## ユーザーシナリオ

### シナリオ A: チケット狙撃手
> Lakers vs Warriors のチケットを Ticketmaster で見つけた。今 \\$340 だけど、過去の傾向から試合直前は \\$280 まで下がるはず。手動で毎日チェックは無理。

→ PriceRadar で URL貼付 + 「\\$300以下」閾値 → 試合 3日前 \\$285 でアラート → 即購入。

### シナリオ B: 出張族
> 来月の東京出張。Park Hyatt 3泊で見積もり \\$1,840。安くなる日は予測不能。

→ PriceRadar で URL貼付 + 「20%下落」閾値 → 出張 1週間前 \\$1,520 でアラート → 予約変更。

### シナリオ C: 旅行コレクター
> 50件以上のホテル・航空券を年間ウォッチ。Excel で手動管理は限界。

→ Unlimited プラン → 全件を1画面で俯瞰 + 朝イチダイジェスト → 月3〜5件は確実に「節約成功」を体感。

## 機能仕様

### 1. URL監視
- **入力**: 公開URL (Ticketmaster, StubHub, Vivid Seats, Booking, Agoda, APA, Hotels.com, Expedia, United, Delta, ANA など)
- **クローリング頻度**:
  - Free: 60分間隔
  - Pro: 15分間隔
  - Unlimited: 5分間隔
- **メタ情報抽出**: タイトル / サムネイル / 価格 / 通貨 / 在庫有無
- **対応サイト数**: ローンチ時 12サイト → 半年で 30サイトを目標

### 2. 閾値アラート
- **絶対値**: 「\\$300以下になったら通知」
- **相対値**: 「20%以上下がったら通知」「最安値を更新したら通知」
- **複合条件**: 「\\$300以下 AND 在庫3枚以下」(Unlimited のみ)
- **通知チャネル**: Push (iOS/Android) / Email / Slack DM (Pro 以上)

### 3. 朝イチダイジェスト
- 毎朝 8:00 (ユーザー TZ) に「監視中アイテムまとめ」を1通配信
- 値下げ・値上げ・新着セールを 1メッセージで把握
- ユーザーは「即時通知」と「ダイジェストのみ」を切替可

### 4. 履歴グラフ
- 過去 30日 / 90日 / 1年の価格推移を折れ線で表示
- 最安値・現在値・差分 (%) のサマリ
- AI による「買い時スコア」(過去傾向 + 在庫推移から判定、Unlimited のみ)

### 5. ワンタップ購入導線
- アラートメッセージから「今買う？」ボタン
- 公式サイトに飛ばすのみ (アフィリエイト報酬は受け取る場合あり)
- **自動購入はしない (事故防止 / Bot 排除ポリシー)**

## 非機能要件

| 項目 | 要件 |
|---|---|
| 可用性 | 99.5% (クローリング失敗時はリトライ) |
| 通知遅延 | 価格変動検知から最大 2分 (Unlimited)、最大 30分 (Free) |
| データ保持 | 価格履歴は 365日、その後集計のみ保存 |
| プラットフォーム | iOS / Android (Capacitor) + Web ダッシュボード |
| 言語 | 英語 / 日本語 (ローンチ時)、半年で 5言語 |

---

## 技術スタック (案)

- **フロント**: React + Vite + TanStack Query
- **モバイル**: Capacitor (iOS/Android 共通コードベース)
- **バックエンド**: Node.js + Fastify, PostgreSQL (価格履歴), Redis (キュー)
- **クローラー**: Playwright + Cloudflare Workers (分散実行)
- **通知**: Firebase Cloud Messaging (Push) + Resend (Email) + Slack API
- **インフラ**: AWS (ECS Fargate) + RDS + CloudFront

---

## 法務・倫理

- **ボット行為と区別**: 連続購入・大量在庫確保は実装しない。価格情報の「閲覧」のみ。
- **利用規約遵守**: Ticketmaster / StubHub の Terms に違反しないクローリング頻度を設定。
- **データプライバシー**: GDPR / CCPA 準拠。ユーザーが入力した URL のみ保存、ブラウジング履歴は取得しない。
