# OpenRyoko デザインガイドライン

## プロダクト世界観

OpenRyoko は「自宅サーバーに常駐する人格 AI」を Markdown と YAML だけで構築できる OSS ゲートウェイデーモン。ターゲットは Indie Hacker・OSS エンジニア・スタートアップ CTO・Vibe Coder。**ターミナル文化 / Git カルチャー / 自作 SaaS 思想** を背景に持ち、洗練されつつも遊び心のあるデザインで攻める。

## カラーパレット (Pattern 1: Developer Premium)

このパレットは **Pattern 1 (LP 1) のみ** に適用する。スライド・IG にも準拠させる。

## タイポグラフィ

- 見出し: `JetBrains Mono`, `IBM Plex Mono` 系の **モノスペース**。プロンプト風 `$ ryoko start`、`> _` カーソル点滅を装飾要素として頻用。
- 本文: `Inter`, `Hiragino Sans` 17px+、行間 1.7。
- アクセント: 緑のアンダースコア・カーソル点滅・コードシンタックスハイライト。

## ビジュアル方針

- ターミナル風 UI（角丸 8px、信号灯ドット 3 つ、コードブロック多用）
- Markdown / YAML / cron 表現の **コードスニペットを実物として配置**（ダミー文字列ではない）
- アイコンは Heroicons / Lucide 系のミニマル線画
- 写真・3D・パーティクル・Canvas は使用しない
- 余白を十分にとり、情報密度より「読みやすさ」と「ハッカー文化らしさ」を優先

## ヒーロー要素

- ターミナルウィンドウのモックを中央に
- `$ npm i -g openryoko && ryoko start` のキータイプアニメ
- 赤・緑の小さな点滅で「稼働中」を示すステータスバッジ

## トーン

- 簡潔・力強い宣言文（「Markdown が、AI になる。」）
- 過度なマーケ言葉禁止（"革命的"等は使わない）
- 開発者文化の言葉を許容（cron / daemon / yaml / cli）

## 禁則

- 白背景の標準 SaaS LP は避ける（Pattern 2 で使う）
- 紫グラデーション・ガラスモーフィズムも避ける（Pattern 3 で使う）
- "AI" の煽り絵文字ロケット ☄️ 連発は禁止
