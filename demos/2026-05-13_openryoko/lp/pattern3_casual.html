// 01

Gateway

localhost:7777 で常駐する REST API。Slack も cron も全部ここに集約。

# systemd で常駐起動
$ systemctl --user start ryoko
GET /api/status   // 200 OK
// 02

Engines

Claude Opus と Codex を 1 コマンドで切り替え。コスト・速度・能力で使い分け。

engine: "claude"  # or "codex"
model: "opus"
// 03

Employees

YAML 一枚で AI 社員が誕生。部署・階層・スキルを全部宣言的に。COO が指示出す。

name: backend-dev
rank: senior
reportsTo: tech-lead
// 04

Skills

SKILL.md 書けば AI が動く。コード不要、Playbook だけ。PR でみんなと共有。

---
name: tweet-summary
description: "X を要約"
---
// 05

Cron

JSON 編集で即反映、再起動ナシ。毎朝のサマリも、夜のバックアップも、全部自動。

{"schedule": "0 9 * * 1-5",
 "prompt": "morning briefing",
 "delivery": {"slack"}}
// 06

Memory

記憶は MEMORY.md と knowledge/。grep で読む、Markdown で書く。Vector DB 不要。

# MEMORY.md
- 亮介 = 泉水亮介, JST
- 結論ファースト・簡潔
- Slack は Slack 記法のみ

$ systemctl --user start \

// FAQ

よくある
質問。

API キーは別途必要？
はい。Claude / Codex（OpenAI）の API キーは自分で取得して config.yaml に書きます。あえて鍵を自分で持つ設計です。OSS だから「裏で何送られてるか分からない」みたいなことは起きません。
Mac でも動く？Windows は？
Mac / Linux はネイティブ動作。Windows は WSL2 推奨です。systemd の代わりに pm2 でも常駐できます。Docker イメージも検討中（コミュニティ PR 歓迎）。
Claude Code / Codex CLI とは何が違う？
Claude Code / Codex は対話用のエージェント、OpenRyoko はサーバーサイドのゲートウェイです。両方を engine として呼び出して使えます。OpenRyoko は cron・Slack・複数エンジン管理・人格永続化が主役で、CLI 対話は副次的。
料金は？
OpenRyoko 本体は完全無料の OSS（MIT）。コストは Claude / OpenAI の API 利用料のみ。サブスクの罠から脱出して、使った分だけ払う設計です。
商用利用は？クライアント案件で使える？
MIT License なので商用 OK。改変・再配布・組み込みすべて自由。ロゴ・名前さえそのままにしてくれれば、あとは煮るも焼くもご自由に。
